# zynqboard_vivado

Vivado 2020.2 project for the **HZHY HZ7020** development board (Xilinx Zynq-7020,
`xa7z020clg400-1I`). It contains the PL side of a Linux + bare-metal AMP design:

* LCD / HDMI / camera video paths built on Xilinx video IP,
* a **1 MSPS ADC capture path** (parallel ADC → AXIS FIFO → AXI DMA → DDR),
* a **dual-channel DDS/DAC waveform generator** (AXI FIFO → DDS → block-ROM → DAC pins),
* the GPIO / PWM / clocking infrastructure used by the PetaLinux image.

The matching Linux side (device tree, kernel, rootfs, boot files) lives in the
sister repository **[zynqboard_petalinux](https://github.com/nailongdw1/zynqboard_petalinux)**.

A pre-built hardware handoff is kept at `HZ_B2B_7z020/system_wrapper.xsa`
(bitstream included), so the PetaLinux project can be rebuilt without running
Vivado first.

## 3. Block design

### 3.1 Video path (LCD, enabled)

```
DDR frame buffer (BG24)
   └─ v_frmbuf_rd ─→ v_axi4s_vid_out ─→ lcd_vtc ─→ rgb2lcd ─→ lcd_rgb_tri_io[23:0]
                                                              lcd_pclk / de / hs / vs
                                                              lcd_bl (AXI PWM), lcd_rst
```

* Frame buffer read through **S_AXI_HP0**, pixel format `BG24`.
* LCD pixel clock is generated by `clk_wiz_0` (33.33 MHz for the 800×480 panel).
* `lcd_id` (AXI GPIO, 3 bits) is used by the Linux driver to select the panel timing.

### 3.2 HDMI and camera (present, disabled in the device tree)

* HDMI: `v_frmbuf_rd → v_axi4s_vid_out → hdmi_vtc → dvi_transmitter_top`,
  with a dynamic pixel clock (`clk_wiz_dyn`, 148.5 MHz), HP1.
* Camera: `ov5640_capture_data → v_vid_in_axi4s → v_frmbuf_wr`, HP2.

Both are usable but currently `status = "disabled"` in `system-user.dtsi`.

### 3.3 ADC capture path (1 MSPS)

```
adc_in[19:0] + 4-bit const
   └─ xlconcat (24 bit) ─→ axis_subset_converter (32 bit, TLAST every 256 beats)
        └─ axis_data_fifo  (asynchronous, depth 8192)
             ├─ s_axis : 1.001 MHz  (FCLK3)   ← ADC sample clock
             └─ m_axis : 100 MHz    (FCLK0)
                  └─ axi_dma_0 (S2MM only, simple mode)
                       └─ cpu1_interconnect ─→ S_AXI_HP3 (64-bit, 100 MHz) ─→ DDR
```

* `adc_clk` is an output pin (Y11) driven by FCLK3 = 1.001 MHz; the ADC samples on
  this clock, so 1 MSPS is the design point.
* The DMA register block and the FIFO register block are accessed by **CPU1**
  through `M_AXI_GP1` → `cpu1_interconnect_0`.
* Simple-mode S2MM, so each transfer is one packet; the subset converter inserts
  `TLAST` every 256 beats (256 samples = 1 KB per descriptor).

### 3.4 DAC / DDS path (1 MSPS update)

```
axi_fifo_mm_s_0 (TX FIFO, 4096 deep, AXI4-Lite @1 MHz)
   └─ AXI-Stream ─→ dds_compiler_0 (phase generator, 12-bit phase width)
        └─ m_axis_phase[15:0] ─→ xlslice [15:4] (12-bit address)
             ├─ dist_mem_gen_0 (4096 × 10) ─→ dds_1[9:0]
             └─ dist_mem_gen_1 (4096 × 10) ─→ dds_0[9:0]
   dds_clk = 1.001 MHz (FCLK3)
```

* Only the DDS phase accumulator is used (`PartsPresent = Phase_Generator_only`);
  the sine table is implemented in the two block ROMs.
* Both DAC channels share the same phase; they only differ by ROM content.
* Frequency step is `f_clk / 4096` (≈ 244 Hz at 1 MHz).

### 3.5 Control and status

| Block | Base address | Purpose |
| --- | --- | --- |
| `lcd_id` (AXI GPIO) | `0x4120_0000` | panel ID strapping |
| `axi_gpio_0` | `0x4121_0000` | 2 PL LEDs |
| `rest_gpio` | `0x4122_0000` | misc reset / status |
| `camera_in/axi_gpio_1` | `0x4123_0000` | camera control |
| `lcd_pl_pwm` | `0x43C0_0000` | LCD backlight |
| `lcd_vtc` | `0x43C1_0000` | LCD timing generator |
| `lcd v_frmbuf_rd` | `0x43C2_0000` | LCD frame reader |
| `clk_wiz_0` | `0x43C3_0000` | LCD pixel clock (dynamic reconfig) |
| `cam v_frmbuf_wr` | `0x43C4_0000` | camera frame writer |
| `hdmi clk_wiz_dyn` | `0x43C5_0000` | HDMI pixel clock |
| `hdmi_vtc` | `0x43C6_0000` | HDMI timing |
| `hdmi v_frmbuf_rd` | `0x43C7_0000` | HDMI frame reader |
| `axi_dma_0` | `0x8040_0000` | ADC capture DMA (S2MM) |
| `axi_fifo_mm_s_0` | `0x83C0_0000` | DAC / DDS FIFO |

> `axi_dma` and `axi_fifo_mm_s` sit in the **GP1** window (`0x8000_0000–0xBFFF_FFFF`),
> i.e. they are reached by CPU1 (and by CPU0 only if it is explicitly allowed to).

### 3.6 Interrupts

`xlconcat_0` merges 7 sources into `IRQ_F2P[6:0]` (GIC SPI 32…38):

| Index | Source | SPI |
| --- | --- | --- |
| 0 | `lcd_out` interrupt | 32 |
| 1 | `lcd_out` irq | 33 |
| 2 | `camera_in` interrupt | 34 |
| 3 | `axi_fifo_mm_s_0` (DA/DDS) | 35 |
| 4 | `hdmi_out` interrupt | 36 |
| 5 | `hdmi_out` irq | 37 |
| 6 | `axi_dma_0` S2MM (AD) | 38 |

The Linux device tree must **not** claim SPI 35 and 38 if CPU1 is to own the
acquisition path.

## 4. Clocking

| Clock | Frequency | Loads |
| --- | --- | --- |
| `FCLK_CLK0` | 100 MHz | `M_AXI_GP0`, LCD AXI interconnect, **`S_AXI_HP3`**, **`M_AXI_GP1`**, **`cpu1_interconnect_0`**, **`rst_hs_100m`** |
| `FCLK_CLK1` | 148.148 MHz | camera path, `S_AXI_HP2` |
| `FCLK_CLK2` | 200 MHz | enabled but unused (available for future high-speed work) |
| `FCLK_CLK3` | 1.001 MHz | **`adc_clk`**, **`dds_clk`**, ADC capture domain (`axis_subset_converter`, FIFO `s_axis`), **HS_DA** (`dds_compiler`, `axi_fifo_mm_s`, interconnect `M02`) |
| `clk_wiz_0` | 33.33 MHz | LCD pixel clock |
| `clk_wiz_dyn` | 148.5 MHz | HDMI pixel clock |

Notes:

* The ADC sample clock and the DAC update clock are intentionally **1 MHz**
  (1 MSPS design point). The PCB was nevertheless laid out with high-speed
  practise (impedance control, length matching) to keep the 1 MSPS edges clean.
* The AXI side of the capture path runs at **100 MHz**, which is what makes
  1 MSPS × 4 B = 4 MB/s comfortable (HP3 could carry ~800 MB/s).
* `rst_hs_100m` (`proc_sys_reset`) is the 100 MHz reset domain for the DMA and
  the AXI interconnect; the 1 MHz reset domain (`cpu1_sys_reset_0`) keeps the
  capture front-end and HS_DA.

## 5. Building the project

1. Open `HZ_B2B_7z020/HZ_B2B_7z020.xpr` with **Vivado 2020.2**.
2. Run **Generate Bitstream** (`synth_1` → `impl_1` → `write_bitstream`).
3. **Re-apply the LCD wrapper patch** — see §7. Without it the LCD pins are
   unconstrained and the display will not work.
4. Export the hardware:

   ```
   File → Export → Export Hardware…  (Include bitstream)
   ```

   or from Tcl:

   ```tcl
   open_run impl_1
   write_hw_platform -fixed -include_bit -force system_wrapper.xsa
   ```

The exported `system_wrapper.xsa` is what the PetaLinux project consumes.

## 6. Using the XSA in PetaLinux

```bash
# on the Linux host, inside the PetaLinux project
cd ~/petalinux/projects/hz7020_fresh
petalinux-config --get-hw-description=/path/to/xsa_dir --silentconfig
petalinux-build
petalinux-package --boot --fsbl images/linux/zynq_fsbl.elf \
                  --fpga images/linux/system.bit --u-boot --force
```

The `xsa_dir` must contain `system_wrapper.xsa` (or `system.xsa`). The resulting
`images/linux/{BOOT.BIN,image.ub,rootfs.tar.gz,boot.scr}` go to the SD card
(p1 FAT32: `BOOT.BIN`, `image.ub`, `boot.scr`; p2 ext4: `rootfs.tar.gz`).

## 7. ⚠ The `system_wrapper.v` LCD tri-state patch (must read)

### What happens

The block design exposes the LCD data bus as three separate ports:

```verilog
input  [23:0] lcd_rgb_i_0;
output [23:0] lcd_rgb_o_0;
output [23:0] lcd_rgb_t_0;
```

Whenever the BD is modified (or `generate_target` runs, or Vivado regenerates the
wrapper before synthesis), `HZ_B2B_7z020.gen/sources_1/bd/system/hdl/system_wrapper.v`
is rewritten in exactly that form.

### Why it is a problem

On this board the 24-bit RGB bus is a **single bidirectional bus** and
`system.xdc` constrains it as `lcd_rgb_tri_io[23:0]`. With the generated form the
pins have no matching port: the LCD bus is left unconstrained and the panel stays
dark, even though synthesis and implementation may still complete.

### Fix — restore the patched wrapper

The patched wrapper is committed in this repository, so the fastest recovery is:

```bash
cd HZ_B2B_7z020
git checkout -- HZ_B2B_7z020.gen/sources_1/bd/system/hdl/system_wrapper.v
```

Then verify:

```bash
grep -c "IOBUF lcd_rgb_tri_iobuf" \
  HZ_B2B_7z020.gen/sources_1/bd/system/hdl/system_wrapper.v      # must print 24
```

> This git-restore trick only works while the BD's **top-level ports are
> unchanged**. If you add or rename top-level ports, re-apply the patch by hand.

### Fix — apply the patch manually

Replace the three port declarations with a single `inout`:

```verilog
//  input  [23:0] lcd_rgb_i_0;
//  output [23:0] lcd_rgb_o_0;
//  output [23:0] lcd_rgb_t_0;
    inout  [23:0] lcd_rgb_tri_io;
```

add 24 IOBUFs (one per bit, 0…23):

```verilog
  wire [23:0] lcd_rgb_tri_i;
  wire [23:0] lcd_rgb_tri_o;
  wire [23:0] lcd_rgb_tri_t;

  IOBUF lcd_rgb_tri_iobuf_0
       (.I(lcd_rgb_tri_o[0]),
        .IO(lcd_rgb_tri_io[0]),
        .O(lcd_rgb_tri_i[0]),
        .T(lcd_rgb_tri_t[0]));
  // … repeat for bits 1 … 23
```

and reconnect the BD instance to those wires:

```verilog
.lcd_rgb_i_0(lcd_rgb_tri_i),
.lcd_rgb_o_0(lcd_rgb_tri_o),
.lcd_rgb_t_0(lcd_rgb_tri_t),
```

The committed wrapper does the same thing with per-bit nets
(`lcd_rgb_tri_i_0 … lcd_rgb_tri_i_23`) and explicit concatenations on the
`system_i` instantiation — either style is fine.

### Recommended workflow

```
edit BD → save → generate wrapper → restore patch → synthesize/implement → export XSA
```

If you forget the restore step, the LCD pins are left unconstrained; the build may
complete but the panel will stay dark (or implementation will complain about the
missing `lcd_rgb_tri_io` port).

## 8. Pin constraints — what to look at

`system.xdc` assigns all board pins at **LVCMOS33**, including:

| Signal | Pin(s) |
| --- | --- |
| `lcd_rgb_tri_io[23:0]` | W18/W19/R16/R17/W20/V20/P18/N17 (R), V17/V18/T17/R18/Y18/Y19/P15/P16 (G), V16/W16/T14/T15/Y17/Y16/T16/U17 (B) |
| `lcd_pclk / de / hs / vs` | P19 / U20 / N18 / T20 |
| `lcd_bl`, `lcd_rst` | M20, L17 |
| `adc_in[19:0]` | V5, U5, V7, W8, U9, U10, W6, Y7, Y9, W10, T11, T5, U7, V8, U8, T9, V6, Y6, Y8, W9 |
| `adc_clk` | Y11 |
| `dds_0[9:0]`, `dds_1[9:0]` | E19…F20, L20…F19 |
| `dds_clk` | G15 |
| `i2c0_scl/sda`, `i2c1_scl/sda` | E18/F17, R19/P20 |

Two **stale entries** are still present in the XDC and should be kept in mind:

* `i2c2_scl_io` / `i2c2_sda_io` (T10 / T11) — there is no I2C2 port in the current
  BD (the camera SCCB is disabled). `T11` is also used by `adc_in[9]`; if the
  camera I2C is ever re-enabled, one of the two signals must move.
* `dds_0[11:10]` / `dds_1[11:10]` — the DAC buses are **10 bits wide** in the
  current design, so these constraints do not match any port.

## 9. Known limitations / roadmap

1. **DDS resolution** — only 12 bits of phase reach the ROM, so the frequency step
   is `f_clk / 4096` (≈ 244 Hz at 1 MHz). A 32-bit phase accumulator (or the full
   DDS sine mode) would be needed for a proper signal generator.
2. **Channel independence** — `dds_0` and `dds_1` share one phase accumulator, so
   they always output the same frequency and phase.
3. **Packet size** — `axis_subset_converter` can only insert `TLAST` every ≤ 256
   beats, so one DMA descriptor carries 256 samples (1 KB). At 1 MSPS this is
   ≈ 3.9 k interrupts/s on CPU1; a custom TLAST generator would allow 16 KB packets.
4. **No I/O timing constraints** — `adc_in` has no `set_input_delay`, `dds_*` no
   `set_output_delay`. Acceptable at 1 MHz, must be added before raising the rate.
5. **FIFO overflow visibility** — the capture FIFO has no overflow counter exposed;
   a full FIFO silently drops samples.
6. **Linux side** — the device-tree `dma` node is still `disabled` and the
   interrupt numbers must be aligned with the concat order (SPI 35 for the FIFO,
   SPI 38 for the DMA) before CPU1 bare-metal code claims them.

## 10. Recent changes

**2026-11-27 — HS clock restructure**

* `S_AXI_HP3_ACLK`, `M_AXI_GP1_ACLK`, `cpu1_interconnect_0` (ACLK / S00 / S01 /
  M00 / M01) moved from FCLK3 (1 MHz) to **FCLK0 (100 MHz)**.
* `axis_data_fifo_0` switched to **asynchronous** mode, depth 256 → **8192**;
  `s_axis` stays on the 1 MHz capture clock, `m_axis` runs at 100 MHz.
* New `rst_hs_100m` (`proc_sys_reset`) for the 100 MHz domain; DMA AXI-Lite and
  MM clocks moved to it.
* ADC sample clock (`adc_clk`) and DAC clock (`dds_clk`) intentionally kept at
  1.001 MHz (1 MSPS design point); HS_DA untouched.
* Result: `synth_1` 0 errors, `impl_1` timing met (WNS +0.252 ns @100 MHz),
  new `system_wrapper.xsa` and bitstream exported.
